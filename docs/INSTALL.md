# FL Backpack 960 — 七日杀 v3.4

基于 FL-bb 二次开发的纯 XML 背包模组。目标版本为 **7 Days to Die V3.4.0**，开发时对照的本机版本为 **V3.4.0 b10**。

## 功能范围

- 固定 **960 格、9 页、全部免负重**，不依赖等级、技能、书籍、药物、背包装备或游戏进度。
- 第 1–8 页每页 108 格（18 列 × 6 行）；第 9 页 96 格（前五行各 18 格，最后一行 6 格）。
- 保留原版搜索、分类筛选、锁格、整理和向容器转移物品功能。
- 九页共用一个原版背包控制器，物品槽使用连续编号；整理作用于整个背包，而非仅当前页。
- 死亡掉落背包扩至 984 格，含 960 格背包及 24 格快捷栏/装备预留。掉落包继续使用原生滚动界面。
- 保持原版制作队列、技能数值、普通容器、载具和全局 UI 缩放设置。
- 无 DLL、无自定义图片，无需额外代码框架。

原版背包装备仍存在，但不再额外增加格数。穿脱或更换品质不应影响固定 960 格。

## 安装

1. 退出游戏，将发布 ZIP 解压。
2. 将 `FL-bb-960` 整个文件夹放入游戏安装目录的 `Mods` 文件夹。
3. 确保路径为 `Mods/FL-bb-960/ModInfo.xml`，其旁边直接是 `Config` 文件夹。
4. 移走旧版 FL-bb 或其他同时修改背包容量/分页布局的模组，避免重复加载。
5. 重新启动游戏并载入存档。新角色无需任何解锁条件；旧角色在重新载入后应用容量配置。

不要将补丁 XML 复制覆盖到游戏 `Data/Config`。更新模组时替换整个旧模组文件夹，不要只覆盖同名文件，否则旧版 `progression.xml`、`XUi` 等补丁可能残留。

联机时使用相同 v3.4 构建与相同模组配置；如需双方安装，使用同一发布包。当前未完成联机实测，不宣称已验证仅服务器安装。

## 使用说明

- 数字按钮 1–9 切换页。第 9 页最后一行只有 6 个有效格子，这是 960 格的精确容量，不是缺失。
- 原生搜索/筛选按物品匹配条件显示格子；切换页面查看其他页的匹配物品，不会自动汇总到第一页。
- 原生规则在筛选启用时禁用整理和锁格操作。先清空搜索、取消分类筛选，再进行整理/锁格。
- 背包格子使用 48 像素布局。不同分辨率、界面缩放和其他 UI 模组下仍需检查文字和按钮可见性。

## 验证状态

已完成对本机 v3.4.0 b10 原版配置的 XML 解析、XPath 匹配、容量/分页/布局边界检查，以及相关原版程序集的静态代码检查。**尚未启动游戏验证，不应将静态检查通过理解为游戏内实测通过。**

请先在测试存档完成以下验收：

1. 新角色无装备、无技能时打开背包，确认 9 个页签、前 8 页 108 格、最后一页 96 格；满包移动时没有负重减速。
2. 在第 1、108、109、864、865、954、955、960 格放置不同物品，跨页拖放和 Shift 转移，确认无重复、错位、丢失。第 954/955 格是末页两段网格的交界，需重点检查。
3. 分别搜索物品名和选择分类，切换全部 9 页检查结果，清空筛选后恢复全部格子。
4. 在第 1、5、9 页锁定物品，整理背包、转移到容器；关闭重开及退出存档重进后锁定状态仍正确。
5. 在满包情况下穿脱各品质原版背包、使用类固醇、技能升级，确认格数始终为 960、没有负重。
6. 测试死亡掉落全部物品，携带满背包、快捷栏和装备，滚动至掉落包底部，确认最后几格可取回；空包正常销毁。
7. 测试普通箱子、制作界面、商人、载具；如用于联机，再检查服务器重启和客户端重连后的物品与锁格状态。

如果日志出现 `XML patch ... did not apply`、`TabSelector` 错误、背包格数超限警告或异常，保留本次 `output_log_client` 日志用于定位。

卸载或更换更小容量模组前，先把扩展格里的物品和不再需要的锁格状态清空，避免容量缩回后无法访问物品。测试死亡流程前备份测试存档。

## 开发者静态检查

在源码目录使用 PowerShell 7：

```powershell
./tools/Validate-Mod.ps1 -GamePath 'X:\SteamLibrary\steamapps\common\7 Days To Die'
```

将路径改成自己的游戏安装目录。工具只在内存中应用 XML 补丁，不启动游戏、不修改原版文件。源码中的 `.work` 为开发备份和静态分析材料，不属于发布包。
